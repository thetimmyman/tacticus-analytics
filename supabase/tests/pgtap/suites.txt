# The pgTAP Gate roster.
#
# WHAT THIS FILE IS
#   The population the `pgTAP Gate` workflow runs, and the count of assertions
#   each rostered suite must produce. `scripts/dev/pgtap-throwaway.sh --roster`
#   reads it; the gate runs nothing that is not named here.
#
# WHY A ROSTER AND NOT `ls`
#   A gate whose population is the directory it tests cannot fail by deletion:
#   removing a suite lowers numerator and denominator alike. This file is the
#   denominator, kept by hand. suites.expected.txt anchors the two totals, and
#   the runner refuses to start unless the roster, this directory and that
#   anchor agree, so roster and anchor edits land in the same commit.
#
# THE `# <count>` IS MANDATORY AND IS CHECKED
#   Each ROSTER line is `<suite>.sql # <assertions>`. The runner requires
#   plan = this count = assertions actually produced, so a suite that drops
#   assertions fails as a count change and one that stops early fails as
#   `stopped early`, not as a pass.
#
# THE DARK SECTION
#   Every `.sql` here that the gate does not run is listed under DARK with its
#   class and measured blocker. A `.sql` in neither section makes the runner
#   refuse to start, so a suite cannot be added invisibly. Classes:
#     RED       at least one `not ok` on the replay lane
#     SHORT     plan > produced: the suite stops early, no `not ok` printed
#     NO-PLAN   the suite never prints a TAP plan
#     ALL-SKIP  every assertion skips, so the suite executes nothing
#     PART-SKIP some assertions skip for a named live-only object
#   Moving a suite out of DARK edits this file and the anchor together, in its
#   own PR. Adding one to DARK requires a measured blocker.
#
# WHAT A GREEN RUN HERE DOES NOT PROVE
#   This is a replay lane: a throwaway container seeded from this repository's
#   own migrations. It cannot see the production privilege surface, live-only
#   functions, or migrations whose verify blocks assert against live data and
#   therefore do not apply here. The runner prints that on every run.
