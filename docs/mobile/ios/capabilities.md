# iOS capabilities and remaining qualification

| Capability                     | Current behavior                                                                                                                     | Qualification still required                                                                                            |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------- |
| Local personal workspace       | Native Player verification, display confirmation, canonical complete Player cache, native paged inventory/progress/roster inspection | Authorized live upstream checks; feature-specific personal-data adapters and full parity                                |
| Local analytics                | Integer raid totals and damage per token, persistent SQLite, offline history                                                         | Full existing feature inventory and canonical migration/history equivalence                                             |
| Guild / Guild Raid             | Optional scope states; Raid requires independently observed Guild on the same key                                                    | Full guild/raid views, actual covered event projection and real upstream qualification; no Raid-only ownership inferred |
| Credentials                    | Native secure field; fixed official HTTPS reads; non-synchronizing device-only Keychain references                                   | Physical locked-device protection, backup exclusion, reinstall and owner recovery checks                                |
| Documents                      | Native scoped picker, strict core-v1 and full Player-cache backup import/export, imported history unverified                         | Full guild/raid and legacy-history archive, cross-platform full-data interchange                                        |
| Lifecycle / pressure           | Background veil, request cancellation, SQLite close/reopen; transactional migration/full-storage checks                              | Physical airplane mode, low-memory/thermal/disk interruption and unattended release launch                              |
| Sharing                        | Six independent Meta/Portal dataset preferences, default off; generation revocation; local Raid staging                              | Reviewed account/guild binding, versioned contribution envelopes/transport, War/Replay payloads, end-to-end revocation  |
| Game-client secret access      | Unavailable; no cross-app private storage or credential harvesting                                                                   | An explicitly authorized and permitted protocol; no fallback bypass                                                     |
| Addons                         | No downloaded executable addons or arbitrary native command bridge                                                                   | Reviewed fixed-operation builtin data adapter and schema validation; feature policy remains visible                     |
| Installation                   | Xcode Simulator app and owned reproducible scripts                                                                                   | Owner-provided device provisioning/signature and physical iPhone/iPad release matrix                                    |
| Upgrade / rollback / uninstall | Future SQLite version rejected; core import restores history; orphan Keychain references pruned on normal reopen                     | Signed physical update/rollback and uninstall verification, complete legacy-history archive recovery                    |

Each unimplemented or unqualified capability remains an acceptance gap. Simulator results, source tests and synthetic onboarding doubles cannot close physical release, full parity or live ownership requirements. The app exposes local scope holding states and sharing unavailability instead of advertising an implemented cloud or client-secret path.

For recovery, explicitly export a full local backup (or a portable core JSON when only core interchange is needed) before replacing an install. Restore through the native picker; the restored data is historical and disconnected. Re-enter keys through the secure field and confirm the displayed Player. The export does not recover keys or consent. On a new install/reopen, the app prunes only its own orphan Keychain references; normal references used by current scope records are retained. Physical Keychain lifetime across uninstall and device backup still requires owner testing.

For an owner-provisioned device candidate, set the owner's existing development team and supplied provisioning profile in Xcode, build the Release scheme, and verify the resulting bundle identifier, provisioning entitlement/device eligibility, signing identity and artifact digest before installation. Launch without a debugger and record the device/OS and artifact evidence privately. A TestFlight/App Store candidate also needs the owner's established signing/distribution setup and review of entitlement/privacy declarations. No workflow here enrolls an account, creates a signing identity, uploads to a store, or publishes a release.
